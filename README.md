# Binary neuron: a trained neural network on a Tiny Tapeout chip

A hardware-software co-design pipeline, built as a vertical slice: one 8-input binary neuron goes through every
stage, from PyTorch training to a chip layout.

1. **Train** the neuron in PyTorch with quantization-aware training, using a straight-through estimator (STE) so
   training sees the same +1/-1 math as the chip.
2. **Export** the trained weights to a C header for the host microcontroller and a test-vector file for the
   hardware test.
3. **Design** the chip in Verilog: XNOR, popcount, and a threshold compare.
4. **Co-verify**: simulate the Verilog and check it against a bit-exact Python reference model on every possible
   input.
5. **Harden** to GDSII with LibreLane, using Tiny Tapeout's GitHub Actions.

Target shuttle: Tiny Tapeout SKY26d (SkyWater 130 nm), one tile.

## How it works

The neuron compares an 8-bit input with 8 trained weights, counts how many bits agree, and outputs 1 if the count
reaches a trained threshold. In +1/-1 terms that's a normal neuron: the sum of input × weight equals
2 × popcount − 8, and the bias is folded into the threshold. See [SPEC.md](SPEC.md) for the exact contract that
every part of the project follows, and [docs/info.md](docs/info.md) for the pinout and how to drive it.

## Repository layout

| Path                          | What it is                                                         |
|-------------------------------|--------------------------------------------------------------------|
| `SPEC.md`                     | The contract: bit order, math, pin protocol                        |
| `model/reference.py`          | Bit-exact integer reference model (the answer key)                 |
| `model/train.py`              | PyTorch quantization-aware training with STE                       |
| `model/export.py`             | Writes the C header and test vectors, after checking reference = PyTorch |
| `src/project.v`               | The chip (Verilog)                                                 |
| `test/test.py`                | cocotb co-verification: chip vs reference on all 256 inputs        |
| `test/test_vectors.json`      | Generated by `export.py`                                           |
| `firmware/host_example.c`     | How a microcontroller loads the model and runs the chip            |
| `firmware/bnn_weights.h`      | Generated by `export.py`                                           |

## Running it

Model pipeline (needs Python with `numpy` and `torch`):

```sh
python model/reference.py   # self-checks the reference model
python model/train.py       # trains, writes model/build/model.json
python model/export.py      # checks reference == PyTorch, writes the header and test vectors
```

Hardware test (needs Icarus Verilog and `pip install -r test/requirements.txt`):

```sh
cd test
make
```

## Automatic checks on GitHub

Every push runs these GitHub Actions:

- **test**: simulates the Verilog against the reference model.
- **model**: runs training and export, and warns if the results differ from the committed files.
- **gds**: hardens the design to a chip layout, runs Tiny Tapeout's precheck, and repeats the test on the
  gate-level netlist.
- **docs**: checks `docs/info.md` and `info.yaml`.

To see the 3D chip viewer, [enable GitHub Pages](https://tinytapeout.com/faq/#my-github-action-is-failing-on-the-pages-part).

## Before submitting to a shuttle

- Rename the top module to `tt_um_<yourgithubname>_bnn` in `src/project.v`, `test/tb.v` and `info.yaml`. It has to
  be unique on the shuttle.
- Put your name in `info.yaml`.
